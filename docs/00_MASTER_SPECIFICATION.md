# nitinsinghverse --- Master Specification

## Project

**Owner:** Nitin Singh\
**Brand:** nitinsinghverse / nitinverse\
**Primary positioning:** AI/ML Student · Full-Stack Developer

## Core statement

Build a premium, fast, mobile-first personal portfolio that demonstrates
real technical ability through projects, AI/ML work, Generative AI
exploration, Three.js experiments, certifications, badges and
professional proof.

## Core philosophy

> Don't just say it. Show proof.

## Proof mapping

-   Full-Stack → Mood Wala
-   AI/ML → Real AI/ML projects and experiments
-   Generative AI → GenAI Lab/projects
-   Three.js → 3D Experiments
-   Professional profile → CV + LinkedIn + GitHub
-   Learning → Learning Journey
-   Skills → Projects + Certifications

## Non-negotiables

1.  Mobile-first.
2.  No horizontal scrolling.
3.  Performance before visual complexity.
4.  Three.js is selective, not everywhere.
5.  Desktop can have richer 3D; mobile gets lightweight 3D or a
    fallback.
6.  Admin controls should make the portfolio content highly dynamic.
7.  Visitor analytics are stored for admin; there is no public realtime
    visitor counter.
8.  Do not invent completed projects, skills, credentials or
    achievements.
9.  Documentation is the source of truth.
10. Do not change unrelated functionality while implementing a task.

## Proposed zero-cost initial stack

-   GitHub for source control.
-   Vercel for public deployment and backend/API functions where
    appropriate.
-   Supabase for PostgreSQL database, authentication and storage.
-   Custom domain is postponed; initial deployment can use a free Vercel
    domain.

## Documentation rule

Before implementation, read the master specification and the detailed
document relevant to the task. If implementation assumptions conflict
with documentation, follow the documentation and report the conflict.
